# Saved study presentation

These adapters create new editions from retained timing-reference and
coast/ignite captures. They call the maintained rich renderer and optional
neutral `pd-report` study components. They execute no policy, controller,
simulation, replay or training. Source captures, manifests and prior report
editions are immutable.

The [plan](../../docs/report_study_qol_plan.md) and
[execution record](../../docs/report_study_qol_execution.md) own scope and receipts.
`render_studies.py ROOT timing|rl NEW_OUTPUT [--pilot]` requires a compiled
`pd_coast_native` library on `PYTHONPATH`. It writes create-only specifications
under an existing allocated ROOT and a new absolute report edition. The pilot
uses labelled retained software subsets. Run each allocation once; a reserved
or failed output is preserved and a subsequent correction needs a new edition.

Study data is presentation, not a qualification authority. Frozen claims and
source intervals remain fixed while filters show descriptive selected subsets.
Fuel differences require both verified landings. Missing metrics, unsupported
inputs and unscheduled variants cannot become zero-valued successful pairs.
Costs retain their separately declared original/repetition denominator.

The common tree, focused previews, rich tools, static Plotly fallback and raw
evidence links remain intact. Study source bindings record original evaluations
and decisions, renderer/library/spec hashes and zero native transitions.
Report publication and server lifecycle are separate actions; this adapter
neither publishes nor starts/stops a server.

`audit_studies.py EDITION SPEC RECEIPT` independently checks complete inventories,
original proof/source identities, every plotted sample and held command, metric
values, shared colour domains and the retained transition matrices. The timing
intervals and all benchmark values must equal the frozen source analysis.
Place the allocation's `workspace-baseline.json` beside the specification.

`check-study-report.mjs` exports a browser-client check for desktop/mobile use.
It traverses every scheduled original through bounded browsing, checks sparse
schedules and exact-zero selections, and follows context through paired details.
Screenshots wait for visible previews to decode and paint. A browser-owned
adapter supplies navigation, JavaScript evaluation and screenshots.

`audit_delivery.py OUTPUTS RECEIPT EDITION...` checks served bytes for every
edition file and its linked source captures/declarations. It uses the established
`starship:8000` endpoint and does not manage the service.
`publish_entry.py ROOT` builds the small visual entry page from accepted release
receipts and exported shared-view SVGs; publication remains an explicit separate
CLI operation. Complete multi-gigabyte study editions stay on the established
report endpoint, linked from the published entry page.

## Complete portable comparisons

The [comparison refinement plan](../../docs/report_comparison_refinement_plan.md)
and [execution record](../../docs/report_comparison_refinement_execution.md)
describe the complete editions now delivered on the shared 8787 publisher.
The original mission tree remains the entry view. Pinned strategy references,
sourced target status, paired trajectories and linked native-time histories are
optional additions; earlier-edition reuse requires an explicit checked join.

`pack_edition.py SOURCE NEW_PACKED` and `audit_packing.py` preserve exact HTML,
numeric literals, proofs and previews. `prepare_portable.py PACKED NEW_EXPORT
VENDOR` separates the small UI from bounded immutable data bundles and vendors
the HTTP-compatible decoder and Plotly. `publish_portable.py EXPORT --title
TITLE` publishes those bundles sequentially through the existing shared service.
It does not manage server lifecycle. Routine tree, paired and rich inspection
uses 8787; explicit raw-capture archives retain their declared source endpoint.

`refine_portable_ui.py EXPORT PREVIOUS_INSPECTION_MODULE [--name NAME]` creates a
new display-only UI directory, reusing already-published data aliases. It binds
the exact old/new inspection source and checks all rich templates. The loader
applies the selected patch only outside the native sample payload. An absent or
ambiguous template binding fails visibly. Previous exports and snapshots remain
unchanged. Publishing this new UI is a separate explicit operation.

`audit_publication.py EXPORT NEW_RECEIPT [--archives] [--ui DIRECTORY]
[--publication RECEIPT]` verifies all served UI/data bytes; optional archives
check every original capture and source declaration too. `check-refinement.mjs`
extends the original browser check with comparison, target, payload-clock,
responsive-history and tail-anchored-vector acceptance on desktop and mobile.

## Inline tree editions

The [inline mission plan](../../docs/report_inline_mission_comparison_plan.md)
and [execution](../../docs/report_inline_mission_comparison_execution.md) bring
selected run previews and typed run rows into the common mission tree. A single
report declares no comparison; a missing declared side remains unavailable.

`prepare_inline_tree.py PREVIOUS_DELIVERY NEW_EXPORT PATCH_SPEC` preflights all
saved rich templates and creates a new small UI over the previous data aliases.
The spec binds a committed source head and exact old/new module sources for
each page kind. Version-2 transport patches retain the version-1 inspection
compatibility path and exclude the scientific rich payload. Publishing the new
dedicated `ui/` directory remains a separate operation through the shared
publisher; no data bundle is republished.

The [compact tree pass](../../docs/report_compact_tree_plan.md) and
[execution](../../docs/report_compact_tree_execution.md) retain the same scientific
data and rich inspection while shortening overview rows. `prepare_compact_preview.py`
creates native layout previews over saved evidence; `check-compact-tree.mjs`
checks geometry, complete group statistics, selectors and lazy inspection.
`prepare_seeded_review.py` verifies maintained scalar/selector semantics and
packages retained seeded overview SVGs, marking missing archived detail links.
`audit_inline_delivery.py --page-url URL` can check a nested entrypoint within
one published bundle; `close_inline_tree.py --kind compact` closes its preservation
ledger. These tools do not run flights, replays, training or service lifecycle.

`audit_inline_delivery.py EXPORT PUBLICATION_RECEIPT NEW_RECEIPT` verifies every
new UI asset and referenced existing data asset. `close_inline_tree.py ROOT
NEW_RECEIPT` checks the final acceptance/gate receipts, source freeze, original
workspace/report/capture hashes, service identities and allocation limits after
owned changes are committed. Neither tool starts a service or executes a flight.
